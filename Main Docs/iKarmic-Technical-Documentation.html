Executive Summary

iKarmic is a production-grade, multi-tenant SaaS platform that delivers AI Employees‑as‑a‑Service. It is not a chatbot builder or a prompt-workflow tool — it is a full reusable Agentic Operating System with a layered architecture designed to make every "AI employee" a data configuration change rather than custom code.

The system ships with four pre-built AI employee roles (SDR, Recruiter, Ops Coordinator, Support), 20+ skills, a governance engine with immutable audit, durable LangGraph orchestration, multi-provider LLM gateway (Claude, OpenAI, Gemini), RAG knowledge base, visual workflow builder (React Flow), TOTP MFA, database-driven SaaS entitlements, and full Postgres Row-Level Security across 46 SQL migrations.

4 AI Employees Live

Aria (SDR), Rio (Recruiter), Otto (Ops), Sage (Support) — each is a Role row with persona, KPIs, scopes, and skill allowlists.

20+ Executable Skills

Code-backed, prompt-declarative, and workflow-composed skills. All go through the same governance gate with scope enforcement and payload-bound approvals.

46 Database Migrations

Full multi-tenant RLS, usage events, schedule runs, webhook triggers, MFA recovery codes, skill definitions, org profiles, system config.

250+ External Integrations

Every tool (CRM, email, calendar, ATS, projects, enrichment, helpdesk) routes through Composio with per-tenant OAuth credential isolation.

Core Purpose & Problem Solved

The Problem

Small and medium businesses cannot afford to hire specialists for every revenue-generating function — SDR, recruiter, operations coordinator, support agent. Manual "AI chatbot" builders require prompt engineering expertise, lack governance, and produce unreliable output. Existing enterprise RPA platforms are expensive and heavy. There is no shrink-wrapped AI workforce that businesses can "hire" off a shelf and trust to operate within compliance boundaries.

The Solution

iKarmic provides role-based AI employees that behave like real staff: they have personas, performance KPIs, allowed skills, SOPs, and permission scopes. They execute autonomously through a governance gate that enforces human approval for high-risk actions (sending emails, escalating tickets), produces immutable audit trails, and surfaces confidence scores for every decision. The platform is delivered as a hosted multi-tenant SaaS so companies sign up and hire AI employees in minutes — no data scientist required.

The strategic moat is the "App Store for AI Employees": new employees are Role rows (data), and new capabilities are reusable Skill definitions that any role can use. Proof: the AI Recruiter reuses 4 of the SDR's skills and adds 4 of its own. A new "AI Finance Assistant" would reuse the same email, calendar, enrichment tools and governance pipeline.

Value Propositions

Enterprise Governance Without Enterprise Cost

RBAC scopes, payload-bound single-use approvals, immutable audit trails — the same compliance primitives Fortune 500s demand, packaged as a SaaS subscription.

Roles-as-Data, Not Classes

Adding a new AI employee is a database row (persona + KPIs + skill allowlist). The same generic runtime executes all roles. Zero code changes per new hire.

Skills Are the Moat

Typed, versioned, reusable skill units. Code skills ship in the box; Prompt and Workflow skills are declarative. An ecosystem of third-party Marketplace skills creates defensibility.

Multi‑Provider LLM Gateway

One API: Claude, OpenAI, Gemini. Per‑tenant key management with no‑restart hot‑reload. FakeLLM for offline dev. Token‑accurate cost tracking per role per skill.

Durable, Checkpointed Execution

LangGraph state persists to Postgres. If an approval pauses a 10‑step goal, the graph survives restarts and resumes from the exact interrupt point.

Self‑Contained Auth + MFA

No external identity provider dependency. JWT+bcrypt+TOTP MFA. Refresh token rotation with single-flight dedupe. httpOnly cookie storage for XSS resistance.

Key Architectural Principles

Roles Are Data

A new employee is a Role row: persona + KPIs + allowed skills + permissions + SOPs. One generic RoleAgent runtime executes any role.

Ports & Adapters

Core defines protocols (MemoryStore, AuditLog, ApprovalStore). In-memory fakes for dev/tests; Postgres/pgvector for production.

Governance Chokepoint

Agents never call skill.run() directly. Every execution passes through the governance gate: evaluate scopes → check approvals → execute → audit.

Dual-Axis Operation

Database axis (Postgres vs InMemory) and LLM axis (Claude/OpenAI/Gemini vs FakeLLM) are independent. Keyless local dev works with both fake adapters.

Integrity Properties:

  • Payload binding — approval is SHA-256 bound to the exact skill name + payload JSON. A different payload cannot ride a stale approval.
  • Single-use consumption — after execution, the approval row is consumed. Replay is impossible.
  • Approve → Execute — POST /approvals/{id}/approve runs the bound skill through the gate. Approving actually triggers the action.
  • Immutable audit — every outcome (denied, approved, executed, failed, low_confidence) produces an AuditEvent that cannot be mutated.

4. Gap Analysis & Value-Add Features

This section identifies critical technical and functional elements that are either missing or partially implemented, assessed for production-readiness impact.

Critical Gaps

Unimplemented Skills CRITICAL

The schedule_followup skill (SDR) returns a hardcoded error: "schedule_followup is not yet implemented — durable scheduling pending." Similarly, schedule_followup is assigned to SDR, Recruiter, and Ops roles. When the LLM selects this tool, the agent fails silently. The scheduler infrastructure exists but follow-up-as-a-skill is unimplemented.

Recommendation: Implement schedule_followup using the existing schedules table and scheduler loop to create one-shot scheduled runs.

No File Upload / Document Parsing CRITICAL

Resume screening (screen_resume) accepts only inline text. The RAG knowledge base accepts only raw text ingestion. No PDF, DOCX, or image parsing exists. This is a fundamental limitation for the Recruiter and Support roles.

Recommendation: Integrate pypdf / python-docx for the KB ingestion pipeline; add a resume_file field type to the marketplace InputField type system.

No Billing / Stripe Integration HIGH

Entitlement enforcement is database-driven with plan tiers. No recurring billing, no Stripe webhooks for subscription lifecycle, no seat-based metering. The platform cannot accept payment autonomously.

Recommendation: Add Stripe integration with webhook handlers for invoice.paid, customer.subscription.deleted, linking to the existing entitlements store.

No Backup / Restore CLI HIGH

No built-in backup mechanism. Tenant data lives in Cloud SQL with no platform-level export/import. Compliance buyers and enterprise customers will demand this.

Recommendation: Ship an ikarmic backup CLI using pg_dump with tenant-scoped exports. Add to the deployment runbook.

High-Impact Gaps

No Skill Versioning & Rollback HIGH

The SkillDefinition.version field exists but no pinning or rollback logic is implemented. If a published marketplace update introduces a regression, all tenants using that skill are affected immediately with no recourse.

Single-Approver Only (No Multi-Approver Workflows) HIGH

Approvals are single-actor: one admin approves or rejects. Enterprise governance requires multi-approver chains, approver groups, SLA timers with auto-escalation, and approve-from-Slack/email with signed action links.

No PII Redaction or Prompt Injection Screening HIGH

The LLM gateway has no middleware for PII detection/redaction on input/output or prompt injection filtering. Data-residency tags and time-of-day execution windows are absent from the gate policy engine.

No AI Finance Assistant (5th Employee) MEDIUM

Named in docs/PLAN.md as a Tier 2 pending feature. Invoice drafting, expense categorization, and reconciliation skills would open the finance/accounting vertical but require new tool adapters (QuickBooks/Xero) and compliance-scoped permissions.

No Multi-Channel Tools (Slack, SMS, WhatsApp, Live Chat) MEDIUM

Email and Slack (approval notifications only) are the only channels. Full Slack, SMS (Twilio), WhatsApp, and live-chat tool adapters are needed for support and sales use cases that require meeting customers where they are.

Operational Gaps

Multi-Instance Deployment Requires Redis MEDIUM

The rate limiter and SSE event bus use in-process state by default. With >1 Cloud Run instance and no REDIS_URL, per-tenant rate limits are enforced per-pod (bypassable) and SSE events only reach clients on the emitting pod. A non-fatal startup advisory is logged but the system operates in a degraded mode.

No Weekly Digest Email LOW

Named in the FEATURE_ROADMAP as remaining minor work. The scheduler is shipped. A weekly summary email (ROI, tokens spent, actions taken per role) would drive engagement and renewal.

No Theme / Branding Live Editor LOW

Branding API exists (logo URL, primary color, brand name) but there is no visual editor. Administrators must know the exact field names and values.

No Org Chart / Manager Role Delegation LOW

departments table and Role.department_id exist. No manager role type decomposes a team goal and delegates to member roles (the CEO pattern one level down). No visual org-chart UI.

No Signed Third-Party Publisher Verification LOW

The marketplace accepts any SkillDefinition. No code-signing, publisher verification, or trust model exists for third-party skills. This is necessary for an ecosystem play but not blocking for V1.
